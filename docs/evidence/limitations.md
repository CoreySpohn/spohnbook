# Limitations and findings

This page records what is known about the current implementations of the book's
conventions: defects, restrictions, workarounds and positive anchors. Chapters
state the conventions themselves and link here, so a finding can be reproduced,
revised or closed without rewriting the explanation it bears on.

Each record has a descriptive identifier that stays fixed, the proposed owner and
the adoption stage that requires its repair (the stages are defined in
{ref}`how to read this handbook <conventions-how-to-read>`),
a status, the affected versions and the evidence. The statuses mean:

| Status | Meaning |
|---|---|
| reproduced | A public reproduction in this repository shows the behavior at the listed versions. A later release may behave differently; the record describes the listed versions only. |
| confirmed by source inspection | The released source code at the listed versions shows the behavior; no executable reproduction is published. |
| historical report; reproduction unavailable | The finding comes from an earlier audit of the suite, and neither a verified affected revision nor a public reproduction was recorded. It is a report to check, not an established current defect. |
| positive anchor | The record describes agreement or a correct convention rather than a defect. It may also carry one of the statuses above. |
| closed | Repaired, with the repairing release and the acceptance result linked. No record has this status yet. |

A record describes the behavior of the named versions, not the scientific
correctness of any other result. A tutorial that runs successfully across a
recorded limitation remains subject to it, and its opening block says so.
Repairs belong to the owning libraries; this page changes when their evidence
does.

(limitations-reproducing)=
## Reproducing a record

Records with the status "reproduced" run from a clean environment:

```console
$ python tools/reproduce_limitations.py            # every reproduction
$ python tools/reproduce_limitations.py phase-angle
```

Each reproduction prints the versions it ran against and the observable quoted in
its record. The observables quoted below were produced with the versions listed
in the record.

build with a workaround shows that the workaround runs; it does not show that the
underlying combination works or that the affected convention is verified.
